# Вопросы и ответы по проекту

Журнал решений из обсуждений. Перед тем как задавать вопрос о проекте, сначала проверьте этот файл. Новые вопросы и ответы пользователя добавляются сюда; неизвестные ответы не заполняются предположениями.

## Платформа и продукт

### Вопрос: Для какой организации и аудитории предназначено приложение?

**Ответ:** Для онлайн-школы дополнительных курсов английского языка.

### Вопрос: Какая первая целевая платформа?

**Ответ:** Приложение работает только в Telegram как Mini App внутри бота.

### Вопрос: Нужно ли сразу поддерживать MAX, VK и WhatsApp?

**Ответ:** Приложения для MAX, VK и WhatsApp должны быть идентичны. Поддержка этих платформ — будущая цель, первая платформа — Telegram.

## Интерфейс и сценарий записи

### Вопрос: Какие разделы нужны в нижней навигации?

**Ответ:** «Учителя», «Личный кабинет», «Настройки». Визуальный ориентир — приложенная картинка с плавающей стеклянной панелью; визуальное направление — «жидкое стекло».

### Вопрос: Что показывать на экране учителя?

**Ответ:** Личное описание, расписание, группы, возраста учеников и примерный уровень английского.

### Вопрос: Что делает кнопка «Записаться»?

**Ответ:** Отправляет заявку администратору на рассмотрение. Администратор подтверждает запись.

### Уточнение: Связана ли заявка с учителем?

**Ответ:** Нет. Заявку рассматривает администратор; связи заявки с учителем в модели нет.

### Вопрос: Где администратор меняет статус заявки?

**Ответ:** Внутри приложения, во вкладке «Личный кабинет» администратора, где отображаются заявки.

### Вопрос: Как ученик узнаёт решение по заявке?

**Ответ:** Придёт уведомление; также администратор может написать ученику в личные сообщения.

### Вопрос: Какие функции есть в ЛК ученика в первой версии?

**Ответ:** Пока только ссылка на урок, надпись «Урок через X минут» и кнопка «Подключиться».

### Вопрос: Что показывается в ЛК администратора и где управлять ролями?

**Ответ:** Во вкладке «Личный кабинет» есть подразделы «Админы», «Учителя», «Ученики»; ученики сгруппированы по подгруппам преподаватель/время. Там можно менять роль пользователя. ЛК администратора также содержит заявки и позволяет менять их статус.

## Пользователи и роли

### Вопрос: Какие роли предусмотрены и как они сочетаются?

**Ответ:** Роли `USER`, `ADMIN`, `TEACHER`. `USER` может быть только пользователем и не совмещается с другими ролями. `ADMIN` может также быть `TEACHER`, и `TEACHER` может также быть `ADMIN`.

### Уточнение: Может ли администратор или учитель обучаться как ученик?

**Ответ:** Нет. Администратор и учитель учиться не могут.

### Решение: Как представить роли в концептуальной ER-модели?

**Ответ:** Роль — отдельная сущность; пользователь связывается с ролью. Причина: при изменении роли не требуется переписывать значение роли у каждого пользователя. Связь должна учитывать, что пользователю могут быть назначены одновременно `ADMIN` и `TEACHER`, а `USER` с ними не совмещается. Конкретная реализация связей и ключи относятся к даталогической модели.

### Вопрос: Что может делать учитель?

**Ответ:** Может менять ссылку на урок и домашние задания. Остальные возможности пока не определены.

### Вопрос: Кто обновляет данные приложения?

**Ответ:** Учителя обновляют ссылки на уроки и домашние задания; администратор обновляет остальное.

### Вопрос: Как приложение получает Telegram ID и ФИО ученика?

**Ответ:** Пользователь должен вызвать `/start`, прежде чем пользоваться приложением, и даёт согласие на отправку уведомлений в Web App. При онбординге показывается вопрос «Согласны ли вы на передачу своего Telegram id и ФИО?», затем отдельными сообщениями запрашиваются фамилия, имя и отчество (необязательно). Точное место фиксации согласия в потоке не определено. Telegram ID передаётся Telegram, ФИО вводит пользователь.

### Вопрос: Какие уведомления нужны?

**Ответ:** Уведомления по заявке и напоминание о занятии за полчаса.

### Вопрос: Какие статусы и переходы заявки нужны?

**Ответ:** `pending → approved/rejected`.

### Вопрос: Что ученик указывает при записи?

**Ответ:** Несколько групп-кандидатов и желаемые дату/время. Часовой пояс — Уфа (`Asia/Yekaterinburg`).

### Уточнение: Нужно ли хранить уведомления и историю их отправки в базе?

**Ответ:** Нет. Типовые событийные сообщения автоматически отправляются ботом в чаты пользователей; историю уведомлений хранить не нужно. Сущность уведомления и связь уведомления с пользователем исключаются из модели данных. Это не отменяет саму отправку сообщений.

## Данные и техническая основа

### Вопрос: Какая база данных подготовлена для разработки?

**Ответ:** PostgreSQL `okoshko_db` доступна локально на `localhost:5432`; материалы по модели находятся в `docs/`. Секреты подключения в репозитории не фиксируются.

### Вопрос: Какой механизм миграций использовать?

**Ответ:** Пока оставить SQL-патчи, без migration framework.

### Решение: Как проверять Telegram Mini App `initData`?

**Ответ:** Использовать официальную HMAC-SHA-256 проверку с bot token из окружения; максимальный возраст `auth_date` — 1 час.

По Telegram ID пользователя приложение должно разрешать или запрещать доступ к соответствующему кабинету; для выдачи доступа администратор/учитель и Telegram ID пользователя связываются назначением роли в базе данных. Страницы администратора и учителя должны быть отдельными страницами/разделами. Это уточнение заменяет прежнюю идею выбирать один из трёх режимов при входе: личный кабинет ученика остаётся отдельным пользовательским кабинетом, а кнопки администратора и учителя размещаются в настройках.

**Ответ:** В настройках также нужны включение/выключение уведомлений, режим контрастных цветов для людей с дальтонизмом и выбор светлой/тёмной темы.

**Ответ:** Использовать Telegram API; локально запускать Docker-образы.

**Ответ:** Это основная HTML-страница приложения, которую отдаёт Java backend и которую пользователь опубликует в боте. Не нужно изображать панель Telegram внутри страницы: её показывает сам Telegram.

**Ответ:** Пока показать каталог, профиль, личный дневник ученика и настройки учителя на тестовых данных, без запросов к backend. Это временный режим для редактирования внешнего вида.

## Решение: форма записи и документ согласия

**Ответ:** Под каждой группой показываются уровень языка, дни недели и время, затем большая кнопка «Записаться». Форма содержит выбор одной или нескольких групп-кандидатов, желаемые дату/время по Уфе и обязательный чекбокс согласия на обработку персональных данных. Ссылка на текст согласия подчёркнута и открывает страницу с PDF. При снятом чекбоксе форма не отправляется.

Форма сейчас демонстрационная и не отправляет запрос в backend. По действующему контракту заявки сервер определяет ученика из проверенного Telegram `initData`; тело содержит `groupIds` и `desiredDateTime`, учитель в заявку не входит. В локальном каталоге есть только демонстрационный текст согласия, поэтому добавлен PDF-заполнитель с явной пометкой, что он не юридический документ. Кто даст утверждённый текст и нужно ли хранить версию/дату согласия в backend - открытые вопросы.

## Новое решение: поля формы заявки

**Ответ:** В форме оставить имя и фамилию ребёнка, номер телефона родителя и согласие на обработку персональных данных. Желаемую дату/время убрать. Удалить поясняющую надпись «Вы начали с группы ...». Чекбокс и ссылку на PDF сохранить; дизайн блока согласия сделать аккуратнее.

Это уточнение заменяет прежнее решение собирать в форме дату/время и выбирать несколько групп. В текущем демо выбранная группа остаётся внутренним контекстом нажатой кнопки «Записаться»; форма не отправляет данные. Действующий API пока требует `groupIds` и `desiredDateTime`, поэтому контракт потребуется пересмотреть до подключения UI.

## Уточнение: онбординг в Telegram-боте

### Уточнение: Что происходит после `/start` и выбора согласия?

**Ответ:** После `/start` бот отправляет приветствие о приложении «Окошко» и просьбу дать согласие на обработку персональных данных, затем отправляет файл и показывает кнопки «Да»/«Нет». При «Нет» доступа к приложению не будет, кнопка запуска не показывается. При «Да» бот запрашивает имя, фамилию и контактный телефон через функцию передачи контакта Telegram. Telegram ID будет запрашиваться позже. После согласия должна появиться кнопка запуска приложения.

### Уточнения, закрытые последующим решением

- Файл и локальный адрес — создать демонстрационные; имя, фамилию и телефон сейчас не собирать и не сохранять.
- Кнопку показывать сразу после «Да», так как сбор персональных полей отложен.
- Telegram ID приходит боту автоматически с update на `/start`; пользовательское решение — отложить его запрос/дальнейшую обработку. Нужно согласовать хранение ID перед подключением реальных данных.

### Решение: локальный макет и сбор данных (уточнено позднее)

**Ответ:** Создать демонстрационный файл согласия. После «Да» открывать страницу Mini App. Сбор имени, фамилии и телефона пока не выполнять. Поскольку сбор пропущен, кнопку показывать сразу после «Да». Последующее уточнение: открываемая страница — основная HTML-страница приложения, не отдельный макет; см. решение ниже.

**Техническое ограничение:** Telegram отклоняет кнопку с `http://localhost`. Синяя кнопка Mini App требует доступный HTTPS URL; до его появления запуск из бота недоступен.

**Результат попытки туннеля:** Cloudflare Quick Tunnel не подключился: локальный DNS недоступен, а из Docker блокируется Cloudflare edge на порту 7844. SSH-туннель `localhost.run` не был использован, так как host key не удалось сверить с опубликованным fingerprint. Публичный адрес не настроен.

### Решение: когда показывать кнопку запуска приложения?

**Ответ:** Отложить кнопку до публикации UI. После «Да» бот подтверждает выбор; запуск из локального HTTP адреса не выполняется.

### Уточнение: Как теперь работает `/start` и кнопка Mini App?

**Ответ (2026-11-06):** После `/start` бот сразу показывает короткую информацию о приложении — без согласия, сбора персональных данных и кнопок в сообщении. Кнопка доступа к приложению уже настроена по умолчанию и должна быть доступна сразу.

## Интеграция UI и backend (2026-11-07)

### Вопрос: Какой контракт заявки использовать при интеграции?

**Ответ (2026-11-07):** В заявке обязательны фамилия и имя ребёнка, телефон родителя, согласие и одна выбранная группа. Заявку отправляет пользователь. Аккаунт ученика создаётся после одобрения заявки администратором; отчество ребёнка не нужно. В данных заявки необходимо сохранить факт согласия на обработку персональных данных, включая разрешение использовать Telegram ID пользователя.

**Текущая рекомендация для согласования:** сохранять в заявке Telegram ID отправителя, данные ребёнка, контактный телефон, выбранную группу, `consentAcceptedAt` и идентификатор/версию показанного текста согласия. До решения не создавать запись ученика; при одобрении атомарно создать пользователя и ученика и зачислить его в выбранную группу. Хранить согласие отдельно от флага уведомлений: это разные цели и разные основания обработки.

**Ответ (2026-11-07):** Telegram ID берётся из аккаунта, из которого пользователь открыл бота/Mini App и отправил заявку. Пользователю нужно сообщить, что заявка, будущий дневник и уведомления привязаны к этому аккаунту; ученик должен отправлять заявку со своего аккаунта, если уведомления должны приходить ему. Если заявку отправил родитель, ID родителя и будет получателем уведомлений.

**Решение (2026-11-07):** создавать базовую роль `user` и связывать Telegram ID при первом открытии Mini App; до одобрения доступны каталог и отправка заявки, личный дневник и настройки закрыты. После одобрения пользователь получает роль `student` и доступ к дневнику. Бот должен показать текст о сохранении Telegram ID для работы личного дневника. Пользователь выбрал сохранение ID при первом открытии Mini App после этого уведомления; согласие с обработкой данных заявки также остаётся обязательным чекбоксом формы.

**Текущая реализация хранения состояний:** PostgreSQL хранит пользователей, роли, профили учеников/преподавателей, членство в группах, уроки, домашние задания и статусы заявок. `/start` пока отправляет сообщение и не сохраняет данные, не ведёт диалоговые состояния. `initData` проверяется защищёнными маршрутами. Тема/контраст сейчас хранятся в `localStorage`; флаг Telegram-напоминаний добавлен отдельным полем, выключен по умолчанию. Роль `user` и серверная сессия добавлены для первого Mini App открытия.

### Уточнение: ссылка группы и домашние задания

**Ответ (2026-11-07):** У каждой группы одна общая ссылка на видеоурок; учитель меняет её в панели для конкретной группы. Учитель там же задаёт домашнее задание группе, и задание относится ко всем ученикам этой группы. В панели учителя должны быть учителя с их уроками и расписанием.

**Ответ (2026-11-07):** Для группы в любой момент действует одна запись домашнего задания на указанный срок; дополнительное задание заменяет текущее, а новый срок означает новую домашнюю работу. Ссылка подключения является атрибутом группы и отображается в ученическом кабинете. Для локальных тестовых данных использовать `example.com`.

**Проверка локальной БД (2026-11-07):** У четырёх групп у одной группы найдены две разные ссылки среди уроков, у остальных — по одной. По указанию пользователя существующие ссылки не переносить; для проверки использовать тестовую ссылку `example.com` на уровне группы.

### Уточнение: ученический кабинет и тестирование

**Ответ (2026-11-07):** Нужно уметь проверять кабинет конкретного ученика, в том числе проверять ссылку и отображение домашнего задания.

**Остаётся уточнить:** Как должен работать локальный просмотр ученика: безопасный локальный selector доступен только в dev-профиле или проверка реальной Telegram-учётной записи? Не использовать передачу произвольного Telegram ID в production API как способ авторизации.

### Уточнение: уведомления и действия администратора

**Ответ (2026-11-07):** Уведомления отправляет Telegram-бот за час и за 5 минут до урока по данным БД о расписании. За час бот спрашивает, выполнено ли домашнее задание. Если уведомления выключены, бот их не отправляет. Настройка уведомлений должна быть выключена по умолчанию и храниться отдельно от согласия на обработку персональных данных. Последующее решение: администратору нужны отдельные действия «Одобрить» и «Отклонить»; предыдущее пожелание оставить только «Обработано» отозвано. Ученик становится учеником после одобрения заявки.

**Уточнение (2026-11-07):** Получателем напоминаний будет Telegram-аккаунт, с которого отправлена заявка. Если нужно, чтобы напоминания получал ученик, заявку нужно отправлять из его аккаунта. Переключатель уведомлений по умолчанию выключен.

**Уточнение (2026-11-07):** Один Telegram-аккаунт может иметь несколько ожидающих заявок. Если администратор одобряет одну из них, остальные его ожидающие заявки отклоняются. У домашнего задания остаются поля «название», «описание» и «срок»; в пределах одной группы одна запись на календарный день Уфы, сохранение в тот же день перезаписывает запись, другой день создаёт отдельную.
