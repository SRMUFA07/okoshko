# HTTP API

## Аутентификация Telegram

Для API заявок клиент передаёт необработанную строку `Telegram.WebApp.initData` в заголовке `X-Telegram-Init-Data`. Сервер проверяет HMAC-SHA-256 подпись и `auth_date`; срок действия — 1 час, согласно [способу проверки Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). Telegram bot token считывается только из `TELEGRAM_BOT_TOKEN`. Если токен не задан, защищённые маршруты отвечают `503 Service Unavailable`; неверные или устаревшие данные дают `401 Unauthorized`.

Роль определяется сервером по Telegram ID и записи пользователя в PostgreSQL. Переданный клиентом student/admin ID не используется для авторизации.

## Текущий пользователь и роли

### `POST /api/session`

Принимает проверенный `X-Telegram-Init-Data`, связывает Telegram ID с записью пользователя и назначает роль `user` при первом открытии Mini App, если у аккаунта ещё нет роли. Ответ содержит роли из PostgreSQL, состояние напоминаний и профиль из подписанного Telegram `user` объекта (`firstName`, `lastName`, `username`, `photoUrl`). Интерфейс отображает этот профиль; имя, username и фото отдельно в БД не сохраняются. Первое использование фиксируется временем и версией уведомления `first-use-v1`; команда `/start` сама по себе запись не создаёт.

### `PUT /api/session/notifications`

Только пользователь с ролью `student` может сохранить `{"enabled": true}` или `{"enabled": false}`. Значение по умолчанию — `false`. Эта настройка отдельна от согласия на обработку данных заявки.

## Каталог учителей

### `GET /api/teachers`

Возвращает каталог преподавателей с именем, фамилией, описанием, стажем и списком групп. У группы возвращаются название, примерный уровень английского и расписание из `groups.class_schedule`.

### `GET /api/teachers/{id}`

Возвращает карточку одного преподавателя. Если преподавателя нет, сервер отвечает `404 Not Found`.

Пример элемента ответа:

```json
{
  "id": 12,
  "firstName": "Имя",
  "lastName": "Фамилия",
  "description": "Описание преподавателя",
  "experienceYears": 4,
  "groups": [
    {
      "id": 3,
      "name": "Группа A",
      "englishLevel": "A2",
      "schedule": "суббота, 12:00",
      "studentCount": 5
    }
  ]
}
```

Значения в примере вымышлены. Поля, отсутствующие в БД, сериализуются как `null`; у преподавателя без групп будет пустой массив `groups`.

Каталог учителей пока не требует Telegram-аутентификации. В ответ включается только число участников `studentCount`, но не данные отдельных учеников или их возраст. Общая ссылка подключения `groups.lesson_link` в публичный каталог не входит; она должна выдаваться только в защищённых кабинетах. Фильтры и пагинация пока не определены; расписание возвращается в том виде, в каком оно хранится в `groups.class_schedule`.

## Кабинет учителя

### `GET /api/teacher/workspace`

Требует проверенный Telegram `initData` и роль `teacher`. Возвращает только группы текущего преподавателя, общую ссылку группы, строки уроков по датам, домашние задания и число участников. Данные учеников не раскрываются.

### `PUT /api/teacher/groups/{groupId}/lesson-link`

Требует роль `teacher` и тело `{"lessonLink":"https://example.com"}`. Учитель может менять ссылку только у группы, закреплённой за ним. Принимаются HTTP(S) ссылки без логина/пароля в URL.

### `PUT /api/teacher/groups/{groupId}/homework`

Требует роль `teacher`. Тело содержит название, описание и местные дату/время срока в часовом поясе школы `Asia/Yekaterinburg`:

```json
{
  "name": "Workbook, Unit 4",
  "description": "Упражнения 2, 3 и 5",
  "dueDate": "2026-11-15T18:00:00"
}
```

Для одной группы и календарной даты Уфы хранится одна запись. Повторное сохранение на тот же день атомарно перезаписывает её; другая дата создаёт отдельную запись.

## Личный дневник ученика

### `GET /api/student/diary`

Требует проверенный Telegram `initData` и роль `student`. Возвращает группы текущего ученика, общую ссылку группы, строки расписания из `lessons` и домашние задания из `homework_assignments`.

## Заявки

Для защищённых маршрутов нужен заголовок `X-Telegram-Init-Data`.

### `POST /api/requests`

Создаёт заявку пользователя со статусом `pending`. Аккаунт определяется сервером по проверенному Telegram `initData`; клиент не передаёт Telegram ID или `studentId`. У пользователя должна быть роль `user`. Профиль ученика создаётся только при одобрении администратором.

Требуется `Idempotency-Key` в формате UUID. Повтор с тем же ключом и данными возвращает прежнюю заявку с `200 OK` и `replayed: true`; повтор ключа с другими данными возвращает `409 Conflict`. Для каждой новой заявки передаётся новый ключ. Несколько ожидающих заявок одного аккаунта разрешены.

```json
{
  "groupId": 3,
  "childFirstName": "Анна",
  "childLastName": "Иванова",
  "parentPhone": "+7 900 000-00-00",
  "personalDataConsent": true
}
```

Все поля обязательны; группа должна существовать, согласие должно быть `true`, имена ограничены 100 символами, телефон — 7–32 символа. Время принятия согласия и версия `consent-demo-v1` записываются вместе с заявкой. Эта версия маркирует демонстрационный текст и должна быть заменена после утверждения текста школой.

Ссылка `/consent.html` открывает страницу с демонстрационным PDF. PDF не является утверждённым документом школы.

### `GET /api/admin/requests`

Возвращает список заявок только пользователю с ролью `admin`.

### `PATCH /api/admin/requests/{requestId}/status`

Только администратор может передать `{"status":"approved"}` или `{"status":"rejected"}`. Одобрение новой заявки в одной транзакции создаёт ученика с данными ребёнка, зачисляет его в группу, меняет роль `user` на `student` и отклоняет остальные ожидающие заявки этого аккаунта. При отклонении профиль не создаётся. Повторное решение получает `409 Conflict`; неизвестная заявка — `404 Not Found`. API не отправляет Telegram-уведомления.
