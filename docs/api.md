# HTTP API

## Аутентификация Telegram

Для API заявок клиент передаёт необработанную строку `Telegram.WebApp.initData` в заголовке `X-Telegram-Init-Data`. Сервер проверяет HMAC-SHA-256 подпись и `auth_date`; срок действия — 1 час, согласно [способу проверки Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). Telegram bot token считывается только из `TELEGRAM_BOT_TOKEN`. Если токен не задан, защищённые маршруты отвечают `503 Service Unavailable`; неверные или устаревшие данные дают `401 Unauthorized`.

Роль определяется сервером по Telegram ID и записи пользователя в PostgreSQL. Переданный клиентом student/admin ID не используется для авторизации.

## Каталог учителей

### `GET /api/teachers`

Возвращает каталог преподавателей с именем, фамилией, описанием, стажем и списком групп. У группы возвращаются название, примерный уровень английского и расписание из `groups.class_schedule`.

### `GET /api/teachers/{id}`

Возвращает карточку одного преподавателя. Если преподавателя нет, сервер отвечает `404 Not Found`.

Пример элемента ответа:

```json
{
  "id": 12,
  "firstName": "Имя",
  "lastName": "Фамилия",
  "description": "Описание преподавателя",
  "experienceYears": 4,
  "groups": [
    {
      "id": 3,
      "name": "Группа A",
      "englishLevel": "A2",
      "schedule": "суббота, 12:00"
    }
  ]
}
```

Значения в примере вымышлены. Поля, отсутствующие в БД, сериализуются как `null`; у преподавателя без групп будет пустой массив `groups`.

Каталог учителей пока не требует Telegram-аутентификации. В ответ не включаются ученики и их возраст: доступ к сведениям о составе групп ещё не согласован. Фильтры, пагинация и формат расписания также пока не определены.

## Заявки

Для защищённых маршрутов нужен заголовок `X-Telegram-Init-Data`.

### `POST /api/requests`

Создаёт заявку ученика со статусом `pending` и связывает её с одной или несколькими группами-кандидатами в одной транзакции.
Требуется заголовок `Idempotency-Key` со значением UUID. Повтор с тем же ключом и теми же группами/временем вернёт прежнюю заявку с `200 OK` и `replayed: true`; тот же ключ с другими данными вернёт `409 Conflict`. Для новой заявки клиент генерирует новый UUID.

```json
{
  "groupIds": [3, 7],
  "desiredDateTime": "2026-11-15T15:30:00"
}
```

`desiredDateTime` — местное время Уфы (`Asia/Yekaterinburg`) без offset в JSON; в PostgreSQL записывается соответствующий `timestamptz`. Все группы должны существовать. Дата/время должны быть будущими, а список групп — непустым, положительным и без дубликатов. Ученик идентифицируется из проверенного Telegram `initData` и должен иметь роль `student`.

#### Текущая демо-форма и расхождение контракта

Демо-форма собирает имя и фамилию ребёнка, телефон родителя и обязательное подтверждение согласия. Выбранная группа остаётся внутренним контекстом кнопки «Записаться»; отдельного выбора групп и желаемого времени в форме теперь нет. Успешное заполнение только показывает локальное сообщение и не отправляет HTTP-запрос.

Текущий `POST /api/requests` пока несовместим с этой формой: он требует `groupIds` и `desiredDateTime`, но не принимает данные ребёнка/родителя или согласие. Telegram-пользователь всё равно должен определяться сервером из проверенного `X-Telegram-Init-Data`; добавлять в запрос клиентский `studentId` нельзя. До интеграции нужно согласовать новый DTO, как передавать группу из кнопки, судьбу желаемого времени и способ проверки/фиксации согласия. При подключении формы также понадобится `Idempotency-Key`.

Ссылка `/consent.html` открывает страницу с демонстрационным PDF. В API пока нет приёма или хранения версии текста и момента согласия. PDF не является утверждённым документом школы.

### `GET /api/requests`

Возвращает заявки текущего ученика, определённого по проверенному Telegram `initData`.

### `GET /api/admin/requests`

Возвращает список заявок только пользователю с ролью `admin`.

### `PATCH /api/admin/requests/{requestId}/status`

Только администратор может передать `{"status":"approved"}` или `{"status":"rejected"}`. Обновление выполняется условно только при текущем статусе `pending`; повторное конкурентное решение получает `409 Conflict`. Неизвестная заявка даёт `404 Not Found`.

Число одновременно ожидающих заявок одного ученика пока не ограничено. API не отправляет Telegram-уведомления.
