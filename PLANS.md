# План проекта «Окошко»

Живой план работ. Статусы: `[ ]` — не сделано, `[x]` — решение зафиксировано или задача реализована и проверена. Backend содержит каталог учителей и API заявок с проверкой Telegram `initData`; есть основная HTML-страница Mini App и минимальный бот с демонстрационным согласием. UI остальных разделов и уведомления по событиям школы ещё не реализованы.

## Подтверждённая концепция

- Приложение предназначено для онлайн-школы дополнительных курсов английского языка.
- Первая целевая платформа — Telegram Mini App (Web App внутри бота).
- Первая страница — каталог учителей.
- Нижняя навигация должна содержать разделы «Учителя», «Личный кабинет», «Настройки» и выглядеть как плавающая стеклянная панель на приложенном скриншоте.
- Экран учителя должен показывать личное описание, расписание, группы, возраст учеников и примерный уровень английского.
- Кнопка «Записаться» отправляет заявку администратору; администратор отдельно подтверждает запись.
- В актуальной демо-форме указываются имя и фамилия ребёнка, телефон родителя и согласие; выбранная группа задаётся кнопкой карточки. Текущий API всё ещё ожидает желаемое время и список групп-кандидатов, поэтому контракт требует пересмотра перед интеграцией.
- После `/start` бот отправляет короткое описание приложения; согласие и сбор персональных данных в боте не запрашиваются. Кнопка запуска приложения настроена пользователем отдельно и доступна сразу.
- Статус заявки меняется внутри приложения. После подтверждения заявки администратором личный кабинет ученика становится активным; до этого он отображается неактивным.
- Вкладка «Личный кабинет» должна показывать интерфейс по Telegram ID и назначенным в БД ролям. В новом предложении вход в интерфейсы администратора и учителя запускается отдельными кнопками в настройках; доступ к ним проверяет сервер.
- Роли: `USER`, `ADMIN`, `TEACHER`. `USER` не совмещается с другими ролями; `ADMIN` и `TEACHER` могут быть назначены одному пользователю одновременно.
- Роль моделируется отдельной сущностью и связывается с пользователем; идентификаторы и способ реализации связи относятся к даталогической модели.
- В личном кабинете администратора отображаются заявки, и администратор может менять их статус.
- Учитель может менять ссылку на урок и домашние задания; прочие данные обновляет администратор.
- Ученик получает уведомление о решении по заявке; администратор также может написать ученику лично.
- Типовые событийные сообщения отправляются ботом; историю уведомлений и получателей в БД не храним, сущности уведомления в модели данных нет.
- Есть пожелание в будущем сделать идентичные приложения для MAX, VK и WhatsApp; это не входит в первую версию и требует отдельной проверки возможностей и ограничений.
- ЛК администратора содержит заявки и подразделы «Админы», «Учителя», «Ученики»; ученики группируются по подгруппам преподаватель/время, там можно менять роли.
- ЛК ученика до подтверждения заявки неактивен; после подтверждения показывает ссылку на урок, надпись «Урок через X минут» и кнопку «Подключиться».
- Визуальное направление: «жидкое стекло».
- Видео `bot-concept-2.mp4` — референс экрана Telegram WebApp; демонстрационные тексты и услуги салона красоты не являются требованиями школы.
