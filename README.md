# Окошко

«Окошко» — приложение для онлайн-школы дополнительных курсов английского языка. Первая целевая платформа — Telegram Mini App (Web App внутри бота). Основной пользовательский сценарий: ученик находит учителя, выбирает занятие и отправляет заявку на запись. Администратор получает её в Telegram и отдельно подтверждает запись.

## Концепция приложения

### Главный экран и навигация

В концепции главного экрана предусмотрена нижняя плавающая панель в стиле жидкого стекла, ориентированная на приложенный скриншот. В ней три раздела:

- **Учителя** — первая страница и каталог преподавателей.
- **Личный кабинет** — раздел ученика.
- **Настройки** — настройки приложения.

Скриншот задаёт только вид нижней панели и активной вкладки; его содержимое «Контакты / Чаты / Настройки» не переносится в приложение.

### Каталог и экран учителя

При выборе учителя открывается его экран с личным описанием, расписанием, группами, возрастами учеников и примерным уровнем английского.

Кнопка **«Записаться»** отправляет имя и фамилию ребёнка, телефон родителя, согласие и выбранную группу в backend. Telegram-аккаунт берётся из проверенного `initData`; профиль ученика создаётся после одобрения администратором. При одобрении остальные ожидающие заявки того же аккаунта отклоняются. Текст согласия пока демонстрационный и должен быть заменён утверждённым текстом школы.

Команда `/start` отправляет короткое описание приложения. Согласие и персональные данные в боте не запрашиваются; приложение открывается существующей кнопкой меню Telegram.

### Роли и заявки

Роли пользователя: `USER`, `ADMIN`, `TEACHER`. `USER` не совмещается с другими ролями. `ADMIN` и `TEACHER` могут сочетаться у одного пользователя. При входе интерфейс может предложить соответствующий режим, но роль и доступ сервер проверяет по Telegram ID и записи пользователя в базе данных; выбор режима сам по себе не выдаёт права.

Личный кабинет администратора содержит заявки и позволяет менять их статус. В нём также предусмотрены подразделы «Админы», «Учителя» и «Ученики»; ученики сгруппированы по подгруппам преподаватель/время. Через раздел администратор может менять роль пользователя.

До подтверждения заявки личный кабинет ученика неактивен (серый). В первой версии после подтверждения он показывает ссылку на урок, надпись «Урок через X минут» и кнопку «Подключиться».

Учителя могут менять ссылку на урок и домашние задания. Остальные данные приложения обновляет администратор.

Ученик получает уведомления о заявке и напоминание о занятии за 30 минут. Администратор также может написать ученику лично. Пользователь должен вызвать `/start`, чтобы начать пользоваться приложением; бот не может сам начать личный диалог.

Визуальное направление — «жидкое стекло». Приложенное видео `bot-concept-2.mp4` — референс экрана Telegram WebApp; его демонстрационный текст про салон красоты не относится к требованиям школы.

В перспективе пользователь хочет идентичные приложения для MAX, VK и WhatsApp. Это не входит в текущий объём первой версии; техническую возможность и платформенные ограничения нужно проверить отдельно. Предварительная рекомендация — переиспользовать общий веб-интерфейс и backend, изолируя платформенные вход, идентификацию и возможности в отдельных адаптерах.

### Образовательный контекст

Целевая организация — онлайн-школа дополнительных курсов английского языка. В личном кабинете предполагаются группа ученика, её состав, ссылка, домашние задания и расписание. Детали доступа и взаимодействия с этими данными пока не заданы.

## Текущее состояние репозитория

В репозитории находится Java 21 / Spring Boot приложение со слоями `controller`, `service`, `repository`, `dto` и `entity`. Защищённые API проверяют Telegram Mini App `initData` и роли пользователя по PostgreSQL. UI доступен на `/app`; каталог и карточка учителя загружаются из `/api/teachers`. Форма заявки отправляет имя и фамилию ребёнка, телефон родителя, согласие и выбранную группу. Администратор на `/admin` может одобрить/отклонить заявку; одобрение создаёт ученика и зачисляет в группу, прочие ожидающие заявки аккаунта отклоняются. Без Telegram-входа или при `?preview=1` отображаются интерактивные тестовые заявки. Кабинет учителя доступен на `/teacher`; управление ссылкой и домашкой связано с backend. Дневник ученика читает расписание, групповую ссылку и домашние задания из БД. Тема и контрастный режим сохраняются локально; серверное предпочтение уведомлений хранится отдельно, но бот ещё не отправляет школьные напоминания. Списки и изменение ролей администраторов, учителей и учеников пока остаются демонстрационными. Бот на `/start` сообщает о сохранении Telegram ID; кнопку запуска Mini App настраивает Telegram отдельно. Контракт API описан в [docs/api.md](docs/api.md), состояние работ и открытые вопросы — в [PLANS.md](PLANS.md).

## Запуск

Для локального бота создайте `.env` по образцу `.env.example` и задайте `TELEGRAM_BOT_TOKEN`. Файл `.env` игнорируется Git. При заданном токене приложение запускает long polling Telegram Bot API: `/start` отправляет короткое описание «Окошка». Бот не запрашивает согласие или персональные данные и не меняет настройку кнопки Mini App. Страница `/app` открывается этой кнопкой без временного токена. После ошибки обработчик не повторяет уже начатый update; отправь `/start` ещё раз для повтора сценария. Не запускайте одновременно несколько экземпляров polling для одного токена.

```bash
./mvnw spring-boot:run
```

В Windows используйте `mvnw.cmd spring-boot:run`. По умолчанию приложение подключается к `jdbc:postgresql://localhost:5432/okoshko_db`. Если параметры локального PostgreSQL отличаются, задайте `DB_URL`, `DB_USERNAME` и при необходимости `DB_PASSWORD` через окружение; секреты не помещайте в репозиторий.

## Проверки

```bash
./mvnw test
```

Тесты проверяют загрузку Spring-контекста и базовые правила сервиса заявок; интеграционные проверки транзакционного одобрения и конкурентных решений ещё нужны.
